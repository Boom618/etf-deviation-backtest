# 微信小程序接入说明

本文档说明如何把 `miniprogram/` 目录跑起来，以及正式发布前必须准备什么。

---

## 一、为什么必须有后端

微信小程序有一条硬性限制：

> 小程序只能请求「服务器域名白名单」里的域名。白名单里的域名必须是你自己
> 持有、能部署服务的 HTTPS 域名。

行情数据来自腾讯财经（`web.ifzq.gtimg.cn`）和东方财富（`push2his.eastmoney.com`），
这两个域名你**无法加入白名单**——加白名单需要在域名根目录放一个校验文件，
你没法往腾讯的服务器放文件。

所以链路必须是：

```
微信小程序  →  你的服务器（已备案 + SSL + 加入白名单）
                    ↓
              腾讯 / 东财 行情接口
```

好消息是：现有的 `etf-deviation-backtest/server.py` **已经有 `/api/kline` 这个接口**，
直接部署上去就能用，不需要改代码。

---

## 二、现在就能做的部分（不需要服务器）

小程序前端已经全部写完，包括：

- 参数面板（标的、区间、均线、买卖偏离率、资金、费率、仓位模式）
- 核心指标卡 + 12 项详细指标
- 三张联动图表（偏离率走势、价格与均线、收益对比）
- 逐笔成交明细页
- 回测引擎（小程序内本地计算，不依赖后端）

### 用开发者工具打开

1. 下载 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)
2. 导入项目 → 选择 `miniprogram/` 目录
3. AppID 处选「测试号」（没有正式 AppID 也能开发调试）

### 关键设置

**详情 → 本地设置 → 勾选「不校验合法域名…」**

不勾这个，所有网络请求都会被拦。

### 接口地址在哪改

`miniprogram/app.js`：

```js
const CONFIG = {
  baseUrl: 'https://your-domain.com',   // ← 改成你的服务器地址
  cacheAge: 1800
};
```

### 没有服务器时怎么调试

小程序会先尝试后端，失败后**自动回退到直连腾讯/东财**（`utils/data.js` 里的
`fetchDirect`）。在开发者工具勾选「不校验合法域名」的前提下，这个回退路径可以直接跑通，
你能在真机上看到完整效果。

只是真机上没有这个「不校验」的开关，所以正式使用还是需要服务器。

## 三、正式发布需要准备什么

### 1. 小程序账号

| 项目 | 说明 |
|---|---|
| 注册 | https://mp.weixin.qq.com/ 注册小程序账号 |
| AppID | 在「开发管理 → 开发设置」里获取，填入 `project.config.json` |
| 类目 | 工具类小程序，需要选对类目（涉及金融数据展示可能要额外资质） |

> ⚠️ **合规提醒**：这个工具展示的是股票行情和回测收益。微信审核对金融类内容比较敏感，
> 小程序内**不要出现任何荐股、收益承诺、买卖建议的表述**。
> 当前实现里已经只展示「程序跑出来的结果」，没有引导性文案，保持这个基调。

### 2. 服务器

| 项目 | 要求 |
|---|---|
| 云服务器 | 1 核 1G 就够（只是转发行情请求） |
| 操作系统 | Linux（CentOS / Ubuntu / Debian 均可） |
| 域名 | **必须已备案**（中国大陆服务器强制要求） |
| SSL 证书 | 必须 HTTPS，免费证书（Let's Encrypt）即可 |
| 防火墙 | 开放 443 端口 |

### 3. 部署后端

```bash
# 1. 上传代码
scp -r etf-deviation-backtest/ user@your-server:/opt/

# 2. 安装依赖（只需要 segno，二维码功能可选）
cd /opt/etf-deviation-backtest
pip3 install segno

# 3. 启动（用 systemd 保持常驻）
PORT=443 python3 server.py
```

**推荐用 systemd**，示例 `/etc/systemd/system/deviation.service`：

```ini
[Unit]
Description=Deviation Backtest Server
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/etf-deviation-backtest
Environment=PORT=443
Environment=HOST=0.0.0.0
ExecStart=/usr/bin/python3 server.py
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now deviation
```

### 4. Nginx 反向代理（给 443 配 HTTPS）

```nginx
server {
    listen 443 ssl;
    server_name api.your-domain.com;

    ssl_certificate     /etc/letsencrypt/live/api.your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.your-domain.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8770;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

server {
    listen 80;
    server_name api.your-domain.com;
    return 301 https://$host$request_uri;
}
```

### 5. 微信后台配置白名单

小程序后台 →「开发管理 → 开发设置 → 服务器域名」→ 修改 `request 合法域名`：

```
https://api.your-domain.com
```

**必须与 `app.js` 里配置的 `baseUrl` 完全一致**（协议、域名、端口都要对得上）。

### 6. 填入地址并上传

```js
// miniprogram/app.js
baseUrl: 'https://api.your-domain.com'
```

改完后在开发者工具点「上传」，到 mp 后台提交审核。

## 四、接口清单

小程序用到的后端接口只有两个：

| 端点 | 方法 | 说明 | 是否必需 |
|---|---|---|---|
| `/api/kline` | GET | 取日线行情（参数 `code`、`market`） | 必需 |
| `/api/symbols` | GET | 取标的清单 | 可选（有内置兜底清单） |

两个接口在现有 `server.py` 里都已实现，**不需要写新代码**。

> 小程序不在后端调用 `/api/backtest`——回测计算在小程序本地用
> `utils/backtest.js` 完成，省一次网络往返，也让离线时能算（用缓存数据）。

## 六、三套引擎的一致性

现在项目里有**三份**回测实现：

| 文件 | 运行环境 |
|---|---|
| `etf-deviation-backtest/backtest.py` | Python 服务端 |
| `etf-deviation-backtest/web/backtest.js` | 网页版 / Android App |
| `miniprogram/utils/backtest.js` | 小程序 |

三份逻辑必须一致。改任何一份后，用多组参数逐字段比对（收益率、基准、年化、
最大回撤、夏普、偏离率统计、逐笔交易明细）。

`miniprogram/utils/backtest.js` 是从 `web/backtest.js` 直接复制来的，只改了导出方式。
**改网页版那份后，记得同步复制过去。**

## 八、常见问题

**Q：提示「url not in domain list」**
A：域名没加白名单。开发阶段在「详情 → 本地设置」勾选「不校验合法域名…」。

**Q：提示「连不上后端服务」**
A：`baseUrl` 配错了，或者服务器没启动、443 端口没开放。

**Q：HTTPS 证书校验失败**
A：证书过期了，或者域名和证书对不上。用 `certbot renew` 更新。

**Q：审核被拒，说涉及金融内容**
A：检查是否有荐股、收益承诺类表述。当前版本只有中性的指标展示，
被拒的话多半是类目选错了，或者审核员误解了用途，可以在备注里说明这是研究工具。

**Q：真机上图表不显示**
A：确认 `<canvas type="2d">` 的 `id` 唯一，且 `_initCharts` 在 `onReady` 里调用
（太早拿不到节点）。
