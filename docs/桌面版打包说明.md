# 桌面版打包说明（Windows / macOS）

把回测工具做成「双击就能用」的桌面软件。打包后不需要目标机器装 Python，
也不需要用户开命令行。

---

## 一、交付物

| 平台 | 文件 | 形态 | 体积 |
|------|------|------|------|
| Windows 10/11 x64 | `ETF回测工具-v1.4.0-win64.exe` | 单文件 exe，绿色免安装 | 17 MB |
| macOS | `ETF回测工具.app` / `.dmg` | App bundle | 约 30 MB |

**绿色版含义**：不写注册表、不建开始菜单项、不带卸载程序。拷走 exe 就是完整软件，
不想要了直接删文件。唯一的落盘数据是行情缓存（`%LOCALAPPDATA%\ETFDviation\cache`），
删掉只是下次要重新联网抓一次。

---

## 二、运行原理

```
┌──────────────────────────────┐
│  原生窗口（系统 WebView）      │  Windows: WebView2 / macOS: WKWebView
│  http://127.0.0.1:8770       │
└──────────────┬───────────────┘
               │ 本机 HTTP
┌──────────────▼───────────────┐
│  server.py（后台线程）        │  复用网页版全部接口
│  ├─ /api/backtest            │
│  ├─ /api/kline               │
│  └─ 静态文件（内嵌的 web/）    │
└──────────────────────────────┘
```

`desktop.py` 做三件事：

1. 找可用端口（优先 8770，被占则让系统分配）
2. 后台线程起 HTTP 服务，等它真正能响应
3. `webview.start()` 开原生窗口；如果 WebView 不可用，退回默认浏览器

所以桌面版和网页版跑的是**同一份前端、同一套回测逻辑**，不存在两套实现漂移的问题。

## 三、Windows 打包

### 环境要求

- Python 3.10+（本机验证用 3.13）
- 首次运行脚本会自动 `pip install pyinstaller pywebview`

### 操作

```bat
build_windows.bat
```

或指定解释器：

```bat
build_windows.bat C:\Python312\python.exe
```

产物：`dist\ETF回测工具.exe`

实际执行的命令（脚本内部就是这句，想手工跑也可以）：

```bat
python -m PyInstaller --onefile --windowed ^
  --name "ETF回测工具" ^
  --icon "desktop\icon.ico" ^
  --add-data "web;web" ^
  desktop.py
```

- `--onefile`：所有依赖（含 Python 解释器、webview、web 资源）压进一个 exe
- `--windowed`：不弹黑色控制台窗口
- `--add-data "web;web"`：把前端打进包内，运行时解压到临时目录

### 目标机器依赖

**WebView2 Runtime**。Windows 11 和较新的 Windows 10 已内置；老系统若缺失，
窗口会起不来，程序会自动回退到默认浏览器打开（功能不受影响）。

要彻底避免这个问题，可让用户装一次微软的
[WebView2 Evergreen Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)（约 2 MB）。

## 四、macOS 打包

### 为什么必须在 Mac 上做

PyInstaller 不是交叉编译器：它把**当前系统的 Python 解释器和动态库**打进产物。
在 Windows 上跑只能得到 Windows 程序，产不出 `.app`。

两条路：

| 方式 | 适用 | 说明 |
|------|------|------|
| 本机跑脚本 | 手边有 Mac | 最直接 |
| GitHub Actions | 没有 Mac | 仓库已配好，免费额度够用 |

### 方式 A：在 Mac 上

```bash
chmod +x build_macos.sh
./build_macos.sh
```

脚本会依次：装依赖 → 用 `sips`/`iconutil` 从 PNG 生成 `.icns` → 打包 `.app` → 用
`hdiutil` 做 `.dmg`。

产物：`dist/ETF回测工具.app`、`dist/ETF回测工具.dmg`

### 方式 B：用 GitHub Actions

仓库根目录已带 `.github/workflows/build-desktop.yml`：

1. 打开仓库的 **Actions** 页
2. 左侧选「构建桌面版」
3. 点 **Run workflow**
4. 跑完在该次运行页面底部下载 `macos-app` / `windows-green-exe`

打 tag（`v1.4.0` 之类）时会自动构建并附到 Release 上。

> `macos-latest` 目前是 Apple Silicon（arm64）。Intel Mac 需要在 Intel 机器上本机跑脚本，
> 或把 workflow 的 `runs-on` 改成 `macos-13`（GitHub 对旧镜像的支持会变动，用前确认）。

### Gatekeeper 拦截

未签名的 `.app` 拿到别的 Mac 上会提示「无法打开，因为无法验证开发者」或「已损坏」。
两种解法：

```bash
xattr -cr /Applications/ETF回测工具.app    # 清除下载隔离属性
```

或在访达里**右键 → 打开 → 仍要打开**（只需一次）。

要彻底干净，需要 Apple Developer 账号做 codesign + notarize（每年 99 美元），
个人自用没必要。

## 五、数据存放位置

| 内容 | 源码运行 | 打包后 Windows | 打包后 macOS |
|------|----------|----------------|--------------|
| 行情缓存 | `etf-deviation-backtest/cache/` | `%LOCALAPPDATA%\ETFDviation\cache` | `~/Library/Application Support/ETFDviation/cache` |
| 运行日志 | — | 同目录 `desktop.log` | 同目录 `desktop.log` |

为什么打包后要换位置：onefile 的 exe 每次启动会把自身解压到
`%TEMP%\_MEIxxxx`，退出即删。若缓存还写在那儿，等于每次开都重新抓行情。

源码运行时仍用项目内的 `cache/`，行为和以前一致。

## 六、排障

| 现象 | 原因 | 处理 |
|------|------|------|
| 双击没反应，无窗口 | WebView2 缺失 / 被杀软拦 | 看 `desktop.log`；装 WebView2 Runtime |
| 窗口空白 | 服务未起来 | `curl http://127.0.0.1:8770/api/info` 看是否响应 |
| 提示端口被占用 | 8770 被别的程序占了 | 程序会自动换端口；也可设 `ETF_PORT=8888` |
| 双击第二次出现卡住 | 旧版无单实例保护 | v1.4.0 已修：会激活已有窗口 |
| 启动慢 3–5 秒 | onefile 要解压 | 正常现象；高频使用可改 `--onedir` 换取秒开 |
| SmartScreen 警告 | exe 未做代码签名 | 「更多信息」→「仍要运行」 |
| Mac 提示已损坏 | 下载隔离属性 | `xattr -cr "ETF回测工具.app"` |
| 中文名 exe 在某些压缩包里乱码 | zip 未按 UTF-8 存文件名 | 用 7-Zip 解压，或直接下载 exe |

日志位置：`%LOCALAPPDATA%\ETFDviation\desktop.log`（Mac 为
`~/Library/Application Support/ETFDviation/desktop.log`）。

## 七、和源码版的行为差异

| 项 | 源码版 | 桌面版 |
|----|--------|--------|
| 启动方式 | `python server.py` + 手动开浏览器 | 双击 exe，自动开窗口 |
| 关闭方式 | 终端 Ctrl+C | 关窗口即退出 |
| 端口冲突 | 直接报错退出 | 自动改用空闲端口 |
| 局域网访问 | 支持 | 支持（默认绑 `0.0.0.0`，二维码可扫） |
| 重复启动 | 各自独立 | 激活已有窗口 |
| Python 依赖 | 需要 | 不需要 |
